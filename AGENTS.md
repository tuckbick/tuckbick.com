# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Commands

```sh
npm run dev       # Vite dev server
npm run lint      # oxlint (config: .oxlintrc.json)
npm run build     # tsc -b && vite build && node prerender.js  -> dist/
npm run lhci      # lhci autorun: Lighthouse (mobile, 3 runs) on dist/ + budget assertions (build first)
npm run test:a11y # Playwright + axe-core accessibility tests on dist/ (build first)
npm run preview   # build, then vite preview
npm run deploy    # build, then wrangler deploy
```

The only tests are the accessibility tests (`npm run test:a11y`). The verification steps are `npm run build` (type-check + prerender), `npm run lint`, `npm run lhci` (performance budgets) and `npm run test:a11y`.

## Architecture

Single-page personal site (React 19 + TypeScript + Vite 8) deployed as static assets on Cloudflare Workers. There is no Worker script and no backend; `wrangler.jsonc` only configures static assets (`not_found_handling: "none"`, so unknown paths 404).

**Build pipeline (prerender/hydrate):** `vite build` emits `dist/index.html` containing an `<!--app-html-->` placeholder. `prerender.js` then starts a Vite server in middleware mode, loads `src/entry-server.tsx` via `ssrLoadModule`, calls `render()` (`renderToString(<App />)`), and writes the HTML into the placeholder in `dist/index.html`. It then loads `src/seo/index.ts` the same way and writes `dist/index.md`, `dist/llms.txt` and `dist/sitemap.xml`. On the client, `src/main.tsx` calls `hydrateRoot` if prerendered markup exists, otherwise `createRoot`. Consequence: components must be SSR-safe (no `window`/`document` access during render; use effects, as `useFavicon` does), and markup must match between server and client or hydration breaks.

**Content vs. components:** `src/App.tsx` renders `Header`, then a `<main>` landmark stacking four sections (`Intro`, `Projects`, `Work`, `Contact`) from `src/content/`. Each section's text/links/images live in a sibling `data.ts` (each exports a typed array/object via an interface declared in that file, e.g. `Project`, `Job`, `ContactLink`, `Intro`; durations use `Duration` from `src/util/formatDuration.ts`, icon platforms use `IconName` from `Icon`), separate from the component. Edit content in `data.ts`; shared UI primitives (Section, SectionList, Gallery, Modal, Icon, Link, ...) are in `src/components/`. Each component has its own co-located `.css` file (plain CSS, no CSS-in-JS).

**SEO / machine-readable output:** `src/seo/` generates Markdown (`markdown.ts`), `llms.txt` (`llmsTxt.ts`) and `sitemap.xml` (`sitemap.ts`) from the same `data.ts` files the components use, so content edits flow to all outputs automatically. The base URL lives in `src/seo/siteUrl.ts`. If you add a new section or change a `data.ts` shape, update the generators too (they use `'role' in project`-style checks for optional fields).

**Static assets:** `public/` is served as-is. Project gallery images go in `public/images/projects/<name>/` and are referenced in `data.ts` by relative path to the 640px JPEG (e.g. `images/projects/marlo/project0.jpg`), with that file's `width`/`height`. They are generated, not hand-made: `node scripts/make-images.mjs [sourceDir]` (sharp; default source `public/images/projects/source/<project>/<name>.<ext>`, HEIC converted via macOS `sips`) writes `<name>.thumb.{webp,jpg}` (256w), `<name>.{webp,jpg}` (640w) and `<name>@2x.{webp,jpg}` (1280w, lower quality) and prints the dimensions for `data.ts`. Every image must have all six files, because the gallery derives the other URLs from the `.jpg` path. Source originals are not committed; delete the source folder after generating so it isn't deployed. `public/images/tucker.jpg` is the site-level photo referenced by the Open Graph/Twitter tags and JSON-LD in `index.html`. `public/privacy.html` is served at `/privacy`. `public/robots.txt` points at the sitemap, and `public/_headers` (Cloudflare static-asset headers) advertises `/index.md` via a `Link` header on `/`, sets content types for `/index.md` and `/llms.txt`, and adds `Vary: Accept` on `/` and `/index.md`, and gives `/images/*` a short cache (`max-age=86400, stale-while-revalidate=604800`; not `immutable`, because image filenames are not content-hashed). Markdown content negotiation (`Accept: text/markdown` on `/` returns `index.md`) is not in the repo: it relies on a Cloudflare dashboard URL Rewrite rule (zone Rules > Transform Rules) that rewrites the path `/` to `/index.md` when the `Accept` header contains `text/markdown`. If it is missing, `/` just returns HTML.

**Security rule (dashboard, not in repo):** A Cloudflare custom rule named "Block unknown paths on tuckbick.com" (dashboard: Security > Security rules) blocks every request that is not a known public path, i.e. it acts as a path allowlist for the site. Its expression matches the paths to block:

```
(http.host in {"tuckbick.com" "www.tuckbick.com"} and not http.request.uri.path in {"/" "/privacy" "/llms.txt" "/index.md" "/sitemap.xml" "/robots.txt"} and not starts_with(http.request.uri.path, "/assets/") and not starts_with(http.request.uri.path, "/images/") and not starts_with(http.request.uri.path, "/fonts/"))
```

Allowed: the exact paths `/`, `/privacy`, `/llms.txt`, `/index.md`, `/sitemap.xml`, `/robots.txt`, and anything under `/assets/` (Vite bundles), `/images/` and `/fonts/`. If you add a new top-level file or route (e.g. a new `public/` file, a `/.well-known/` path, a favicon file, or a new generated output), update this rule in the dashboard too, or the new path will be blocked. Keep the list in sync with `public/` and the prerender outputs.

**Conventions:** `Link` (`src/components/Link/`) opens in a new tab and uses `rel="noopener noreferrer"`, except links to `tuckbick.com` and subdomains, which keep the referrer. Gallery images need `alt` text in `data.ts` (also used in the generated Markdown), and gallery thumbnails are accessible buttons that open the `Modal`. URLs for the generated image variants come from `imageSources()` in `src/components/Gallery/imageSources.ts`. Thumbnails load the 256px WebP via `<picture>` (JPEG fallback). The modal image uses `srcset` 640w/1280w with `MODAL_IMAGE_SIZES` (keep it in sync with `.modal` sizing in `Modal.css`), shows the cached thumbnail as a background placeholder, and fades in on load. Hovering or focusing a thumbnail prefetches the modal image via `prefetchModalImage()`. `formatDuration` collapses identical start/end dates into a single date.

**`index.html`** holds the metadata (SEO/Open Graph tags) and expanded JSON-LD structured data, and the favicon is an inlined data URI (swapped on an interval by `src/content/Header/useFavicon.ts`).

**Fonts:** Nunito (body) and Zain (headings) are self-hosted as static latin-subset `.woff2` files in `public/fonts/` (from `@fontsource`, OFL licenses alongside), declared with `@font-face` (`font-display: swap`) at the top of `src/index.css`. Only the variants the site uses are included: Nunito 400 and 600 (body; `.link` at 600) and Zain 700 (headings) and 400 italic (the `<em>` roles inside headings; Zain has no 700 italic, and `font-synthesis: none` is set in `:root`, so those render at regular weight rather than faux-bold). `index.html` preloads the two above-the-fold files (Nunito 400, Zain 700) with `crossorigin`, and `public/_headers` gives `/fonts/*` a long immutable cache. If you add a new weight/style (e.g. `<strong>`, Nunito italics, a new `font-weight`), add the matching `.woff2` and `@font-face` rule, or it will fall back to the nearest face. Non-latin characters are not covered by the subset.

**Accessibility tests:** `tests/a11y/` holds Playwright specs (`page.spec.ts`: axe on the page and the full tab order; `dialogs.spec.ts`: axe on the open gallery and work dialogs, keyboard open/close, close-button focus, focus return, gallery arrow keys). `playwright.config.ts` serves the built `dist/` with `vite preview` on port 4173 (Chromium only), so rebuild before running them after changing `src/`. `checkA11y(page, include?)` in `tests/a11y/axe.ts` runs axe with the WCAG 2.0/2.1 A and AA tags, fails on `serious`/`critical` violations and reports the rest as warnings (console and test annotations). The tests are type-checked through `tsconfig.node.json` (`module: nodenext`), so relative imports need the `.ts` extension (`import { checkA11y } from './axe.ts'`). The tab-order test lists every focusable element by accessible name, so adding, removing or renaming a link, project, gallery image or job means updating that list. `Modal` keeps a dialog mounted once it has been opened (`wasDialogOpen`), so closing it goes through the native `close()` and the browser returns focus to the trigger; don't go back to unmounting it on close. The README "Accessibility" section is the site's accessibility statement: keep it in sync with what the tests check.

**Performance baseline:** `docs/performance.md` records mobile Lighthouse and WebPageTest numbers (date, commit, tools, settings, and steps to reproduce them). Budget and monitoring work uses them as starting thresholds. Add a new dated baseline instead of editing the old numbers. The budgets enforced in CI live in `lighthouserc.json` (`ci.assert.assertions`, checked with `aggregationMethod: "median-run"`). Their values and reasoning are in the "Budgets (Lighthouse CI)" section of `docs/performance.md`. When you change a budget, update that section too. Adding gallery images uses up the `resource-summary:image:size` budget.

**Deploy:** pushing to `main` runs `.github/workflows/deploy.yml` (job `build-and-deploy`: `npm ci`, `npm run build`, `npm run lhci`, upload `.lighthouseci/` as the `lighthouse-reports-<attempt>` artifact, even on failure, `npx playwright install --with-deps chromium`, `npm run test:a11y`, upload `playwright-report/` as the `a11y-report-<attempt>` artifact, even on failure, then `wrangler-action`), which needs the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repo secrets. A failing budget or accessibility test stops the job before the publish. Pull requests to `main` run the same workflow, but the publish step is skipped (`if: github.event_name == 'push' && github.ref == 'refs/heads/main'`). The steps before it use no secrets, so they also work on PRs from forks. A `concurrency` group cancels superseded PR runs but never a `main` deploy. Lighthouse CI reports go to the filesystem/artifact only, not to public temporary storage. PR descriptions start from `.github/pull_request_template.md`. PRs are self-reviewed and self-merged (no approver), and its checklist mirrors the verification steps and gotchas above (SSR safety, SEO generators, image variants, the Cloudflare allowlist, docs). Keep it in sync when those change.

## Keeping docs current

When a change affects how the project is built, structured, or edited (new/renamed/removed files or directories, build pipeline or command changes, new content sections, changed conventions, deploy setup), update `AGENTS.md` and `README.md` in the same change. Skip updates for changes that don't alter anything those files describe (e.g. copy edits in `data.ts`, styling tweaks, bug fixes).
